----- ORIGINAL R1717 PLAN (historical where superseded) -----
NEXT CONSTRUCTION BOUNDARY: RECOVER DIMENSION FROM RAW INPUT
Prepared after R1717. Design only; none of the new loader claims below are
formalized yet. Existing SeededEnumeration covers the subsequent per-map
computation, including seed setup, all rows, exact records and cleanup.

INPUT CONTRACT
The original Transpose.encode has no size header. For valid inputs its
length is L(N)=N*N*entryBits(N), N>=1. The loader must produce a marked
little-endian word of value N and length <= size(N+1), from the original
blank initial workspace. It must retain input contents and account for
input-head movement, every marker and all temporary tapes. A promise that
the length is L(N) is legitimate for the final valid-input theorem; supplying
N or a binary length word as extra data is not.

PROPOSED ALGORITHM
1. Scan the read-only input once. Maintain an extensible binary length
   counter, paying physical carry scans and rewinds. Prove an amortized
   O(L+1) bound: a fixed-width full scan for each input bit would instead
   introduce a log L factor and is not adequate for this first phase.
2. Starting with candidate k=1, compute k*k*entryBits(k) and compare with
   the stored input length. Reuse paid addition/scaling primitives. Obtain
   entryBits(k) from the significant bit count of k-1, with the k=1 case
   handled exactly as the original definition.
3. Increment k until equality; a greater-than result can reject invalid
   lengths. Prove strict increase of L(k) for k>=1 and termination at N
   on valid inputs. The algorithm must not contain a supplied loop bound N.
4. Trim high zeroes of the candidate word by a paid scan/copy; restore the
   promised marked representation and short-word length. A padded counter
   is not automatically short enough for the current native cost theorem.
5. Clear temporary arithmetic words and restore required heads before
   calling SeededEnumeration.native_call.

WHY THE SEARCH MAY FIT THE BUDGET
Using k paid additions for k*k costs O(k log L) on O(log L)-bit words;
summing k=1..N gives O(N^2 log L). Computing the extra entryBits(k) factor
by O(log k) additions contributes O(N log^2 L). On valid inputs
log L=O(entryBits(N)), so these terms are O(L). This is a prospective cost
argument, not a completed native trace or proved formal bound. Every
scratch reset and factor-width fit still needs checking. The N=1 case
requires an explicit constant bound.

REUSE / STOP RULE
First inspect existing Counter/NativeCounter and the native compiler before
adding code. The current arithmetic programs preserve the external input
head; raw input reading needs an actual finite transition table/interface.
Do not replace the length scan by a word-RAM primitive, free input-length
oracle, supplied dimension header or uncharged width computation. Do not
rebuild the already proved per-map record generator.

AFTER LOADING
Map-specific C gives map-specific record widths. Fixed multi-map assembly
must choose and physically implement a common width/tag convention, or
prove and pay for explicit parsing. Inverse symmetrization, graph records,
dedup/color normalization, clocks/fetch/payload and full generator remain.
Unconditional expanding-family existence, affine motion and contracting
recursion are independent remaining theorem obligations. All six intended
families remain in scope. Referee agents wait until all are formalized.
