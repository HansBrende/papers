R1910 import coupling diagnostic — 21 October 2026
Read-only review; no Lean/Lake execution or repository changes by reviewer.

Cause
ClosedRationalExpansion imports ContinuousNativePadding solely to support
three adapter declarations. Analytic definitions in the same module cause
ConditionalSpectralExpansion and then RationalMobiusAction/RealMobiusAverage
and the large SL2 analysis chain to import the entire native compiler.
Consequently compiler proof edits invalidate analysis that never uses it.

Smallest complete boundary split
Move these declarations unchanged to a new ClosedNativePadding module:
- RationalUnitMobius.restricted_vertex_expansion
- PaidPadding.restricted_uniform_computation_with_cut
- PaidPadding.restricted_uniform_linear_tasks_macrostar

The new bridge imports ClosedRationalExpansion and ContinuousNativePadding.
ClosedRationalExpansion retains only RationalUnitRestriction as its import.
That foundational closure already supplies OverlapExpansion.mapImageUnion,
RationalFamilyGraph.rationalFamilyMaps, and the clipped/augmented rational API.
Add an explicit ContinuousNativePadding import to UnconditionalPaidPadding,
which actually uses native padding, and a ClosedNativePadding import to
SupportAxioms, which preserves audit coverage of the moved adapters.
