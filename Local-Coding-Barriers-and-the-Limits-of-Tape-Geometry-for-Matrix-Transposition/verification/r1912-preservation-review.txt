SOURCE-PRESERVATION CHECK
external/temporary/r1912-preservation-check.py is read-only and has two modes:
- Candidate review, no Lean execution: scans scopes and commands and checks the
  baseline source hashes and complete exact audit-name list.
- --check-current: requires exact concatenation of every original non-import
  source body in planned order. Only whitespace may separate complete bodies.
  All ungrouped non-import source text must be byte-for-byte identical. Deleted
  files must be precisely the planned non-destination members. New target
  imports must be the first-occurrence-ordered external union after remapping;
  consumer imports must be the mapped/deduplicated old list. It rejects dangling
  deleted imports, missing local imports, extra sources and cycles.
- Optional --axioms-log verifies the exact 6,297-name set and allows only the
  original standard axioms, propext/Classical.choice/Quot.sound.

The checker deliberately rejects changed proof text rather than approximating
semantic equivalence. A later import-splitting change requires a separate explicit
preservation review and must not be hidden by relaxing this check indiscriminately.
The lexical hazard scanner is conservative, not a full Lean parser.

BENCHMARK REVIEW
verification/r1912-source-endpoints-benchmark.py preserves the five original bodies,
uses the pinned Lake environment, explicitly isolates package root and outputs in
scratch, checks live source hashes before and after every run, and alternates arm
order for repeat trials. The wait4 replacement avoids the denied BSD time sysctl;
wall time is perf_counter and CPU/RSS are OS child-resource data.

The split arm imports previously validated original predecessor artifacts, whereas
the merged arm has the same preceding declarations in the current file. This is a
valid controlled measurement of repeated process/import/elaboration work, and every
proof is elaborated and kernel-checked in both arms. It is not a scratch rebuild of
the full predecessor graph and not a whole-Lake wall-time measurement. Sum of the
five sequential split timings is meaningful here; sums of overlapping Lake jobs
are not total build time.

Use three paired alternating trials plus import-only probe, comparable warm-cache
conditions, and the agreed >=35% median elapsed saving gate. Review stdout/stderr
for warnings, return codes and memory as well as timing. One pilot pair or an old
historical 15-second/module figure does not establish the production speedup.
No shared cache deletion/trace rewriting/timestamp manipulation is warranted.
