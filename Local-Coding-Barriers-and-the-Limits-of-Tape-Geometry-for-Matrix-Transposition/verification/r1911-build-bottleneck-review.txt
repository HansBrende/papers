Main finding
The recurring wall time is principally architectural: a very long serial chain of small compiler modules repeatedly loads a large shared environment. Increasing parallelism cannot parallelize a direct dependency chain. This diagnosis is supported by local import-graph structure and observed per-module timings; the share specifically attributable to import/startup remains to be measured.

Why not simply narrow Mathlib imports now?
NativeMicrocode imports Transpose.Tape.Run, which imports the protected original paper's Transpose.Tape.Defs, whose first line is import Mathlib. Consequently every native compiler module already imports all Mathlib transitively. Replacing our own Mathlib.Tactic imports with narrower imports cannot remove that inherited closure. The original paper is read-only in this task. R1910's split did correctly remove compiler dependencies from232 analytic modules, but the remaining long compiler chain is genuine and not another equivalent accidental analytic import.

Why not alter Lake cache behavior or use proof stubs?
Installed Lake's Build/Module.lean builds each module after its presetup/import artifacts are available, hashes input and imported artifacts, and restores outputs only on verified matching traces. Bypassing these hashes would undermine validation. No such change is proposed.
The installed Lean supports its newer public/private module system, but legacy root imports load all transitive/private data (Lean/Environment.lean around2121; Lake/Build/Module.lean around306–359). A selective migration would therefore need a separate carefully audited compatibility exercise and axiom-inspection strategy. It is not the bounded next benchmark, and no theorem is being replaced with an unchecked interface.

Benchmark pitfalls
- One pair is a pilot, not a stable speed estimate; normal OS cache warmth and concurrent system activity matter. Three alternating pairs provide a better comparison.
- lake env lean checks reproduce proof elaboration/kernel checking and import cost but not every Lake build/artifact-export overhead. Validate wall-time improvement in one normal full build after adopting a production merge.
- Split copies import current, normally verified original predecessor artifacts; merged proof bodies have earlier definitions physically present. No foreign or stale source artifacts are substituted.
- Aggregate source statements and proof bodies are unchanged, but module-local scopes and private-name collisions can complicate other groups. The selected group has none of those private/local declarations and keeps each balanced namespace block.
- Preserve the complete axiom audit at its exact final R1911 count and all six endpoint contracts when any source organization change is applied. Reuse the existing exact-name audit rather than inferring correctness solely from text comparison.
