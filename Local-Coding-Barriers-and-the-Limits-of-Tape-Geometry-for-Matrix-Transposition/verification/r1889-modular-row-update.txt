NEW R1889 RESULTS
1. ModularRowWord.operation_value: for equal-width little-endian Boolean
   lists a,x of length W, the checked carry machine returns a W-bit word
   whose value is (value(a)+value(x)) mod2^W for addition, or
   (value(a)+2^W-value(x)) mod2^W for subtraction. Addition imports the
   previous RepeatedAdd.addWord_value; subtraction is a short consequence
   of BinaryCarry.subtraction_identity and value_lt using Nat modular laws.
   rawOperation_value reverses the lists to state the exact MSB-first
   semantics of017. These semantic reversals do NOT claim unpaid physical
   bit-order conversion. Width0 is included in the arithmetic statements.

2. PaddedWorkSchedule: a generic work routine may be run for a fixed public
   budget N. Its halt/reject instructions become actual stationary
   self-jumps, and its trajectory equals the existing frozen work run.
   A checked active trace of length t<=N to a stopped state therefore
   reaches the same work state after exactly N paid scheduled steps.
   The schedule is active at every tick; the existing scheduled compiler
   then halts at its external public clock N. No input-dependent stopping
   duration or uncharged wait is introduced. At every prefix n, each head
   is at distance<=n from its initial coordinate.

3. RepeatedAddCalls/RepeatedAddBody now contain the shared caller proofs:
   arithmetic_call_to handles both addition and subtraction; copy_call_to,
   recycle_call_to and jump_trace_to accept an actual target program with
   the required checked instruction equations. update_trace_to composes
   the arithmetic, accumulator erase, result copy, scratch erase and four
   linking jumps, giving a real trace of length<=18W+30. Existing public
   addition_call/copy_call/recycle_call/jump_trace/body_trace statements
   retain their previous bounds and specialize these shared proofs.
   The old body still includes its paid entry jump, hence18W+31.

4. RowArithmeticUpdate specializes that shared body to a controller that
   stops at the return label, then applies PaddedWorkSchedule. For every
   sub flag, equal-width a,x, fuel word, starting coordinates, external
   input position and prior output, native_complete proves exact native
   execution and halting at18W+30. The resulting acc is the modular result;
   factor=x, fuel and the marked zero word are preserved; scratch is reset
   to preparedOutput (a START marker and otherwise blank tape), and every
   work head, input position and output accumulator is restored.
   native_prefix_excursion proves the bound for actual native prefix
   configurations, not only an abstract path. For W>=1,18W+30<=48W.
   fixed_resources:5 tapes,5 alphabet symbols,99*(18W+31) control states.
   The operands/zero/scratch are explicitly prepared in the initial
   configuration. Raw loading and final output/cleanup are not included.

PREFER THE MOVE-BEFORE-READ VARIANT (7W), to simplify the zipper proof.
The6W sanity-check variant is not worth optimizing or formalizing as well.
Concrete schedule for W>=1, bank at row MSB and accumulator at its MSB:
- One actual jump initializes carry=sub.
- Move both heads rightW ticks, just beyond their respective rows.
- Repeat W times, FOUR paid ticks each:
  1.move both heads left;
  2.read bank a into finite mode, keeping carryc;
  3.read accumulator x, set u=x XOR sub, y=a XOR u XOR c,
    c'=majority(a,u,c), saved=(a if sub else y);
  4.write banky and accumulatorsaved, stay in place, retain c'.
- Move only bank rightW to the next row; accumulator is already at0.
- Pad W-1 stationary ticks. Total1+W+4W+W+(W-1)=7W exactly.
Starting just beyond a field gives the inner scan a simple zipper invariant:
its left lists begin with the LSB-first operands. Each cycle pops one cell
from each left list, then writes its result at the new head; induction
concatenates the reversed outputs on the right. Reuse existing zipper
write/move denotation lemmas rather than reprove tape semantics.
